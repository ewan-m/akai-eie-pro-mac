# AKAI EIE Pro USB Audio Driver for Linux

A custom Linux kernel driver for the AKAI EIE Pro USB audio interface, providing full audio input/output functionality with multi-format support.

## 🎵 Features

- **Full Duplex Audio**: Simultaneous playback and recording
- **Multi-Format Support**: S32_LE, S24_LE, S16_LE capture formats
- **Multi-Channel**: Up to 4-channel output, 1-4 channel input
- **Sample Rates**: 44.1kHz, 48kHz, 88.2kHz, 96kHz
- **Professional Quality**: 24-bit audio processing with proper bit manipulation
- **PipeWire/PulseAudio Integration**: Works seamlessly with modern Linux audio systems

## 🎛️ Audio Configuration

### Volume Management
The driver uses proper bit scaling without artificial gain. PipeWire's automatic gain control typically settles at 50% volume for optimal levels:

```bash
# Check current volume
pactl list sources | grep -A5 "AKAI EIE Pro"

# Manually adjust if needed
pactl set-source-volume alsa_input.pci-0000_16_00.0-usb-0_6.4.4.stereo-fallback 50%
```

### Format Selection
Applications can choose from multiple formats:
- **S32_LE**: Best quality, 32-bit samples (recommended)
- **S24_LE**: Professional quality, 24-bit samples
- **S16_LE**: Standard quality, 16-bit samples

## 🔧 Adjustments & Customization

### Hardware-Specific Adjustments

**USB Path Detection**: If your USB path differs from `1-6.4.4`:
```bash
# Find your device path
lsusb -t | grep -A5 -B5 "09e8:0010"

# Update reload script USB path
vim reload.sh  # Edit the echo "1-6.4.4" lines
```

**Sample Rate Priority**: Modify preferred sample rates in `akai_eie_pro.c`:
```c
.rates = (SNDRV_PCM_RATE_44100 |
          SNDRV_PCM_RATE_48000 |    // Default preference
          SNDRV_PCM_RATE_88200 |
          SNDRV_PCM_RATE_96000),
```

### Performance Tuning

**Buffer Sizes**: Adjust for latency vs. stability in `akai_eie_pro.c`:
```c
.buffer_bytes_max = 1024 * 1024,    // Increase for stability
.period_bytes_min = 64,             // Decrease for lower latency
```

**URB Count**: Modify USB request blocks for different systems:
```c
#define PLAY_URB_CNT 4    // Increase for stability
#define CAP_URB_CNT 2     // Usually sufficient
```

## 📚 Technical Details

### Driver Architecture
- **Single-file design**: All functionality in `akai_eie_pro.c`
- **Bulk endpoint capture**: Uses endpoint 0x86 with 4096-byte buffers
- **Bit manipulation decoding**: Based on pokus.c reference implementation
- **Multi-format output**: Proper bit scaling for each ALSA format
- **ALSA integration**: Standard PCM interface with hardware constraints

### Audio Processing
- **Raw bit extraction**: 64-byte frames → 4-channel 24-bit samples
- **Format conversion**: Proper scaling to S16_LE/S24_LE/S32_LE
- **No artificial gain**: Uses raw hardware values with correct bit positioning
- **Automatic playback URBs**: Required for capture functionality

## 🎯 **Installation Methods Explained**

Linux kernel modules can be loaded in different ways with different persistence levels:

| Method | Command | Persistence | Auto-Loading | Use Case |
|--------|---------|-------------|--------------|----------|
| **Runtime Loading** | `insmod` / `./reload.sh` | Until reboot | No | Development/Testing |
| **Production Installation** | `./install.sh` | Survives reboot | Yes | End-user deployment |

### **Runtime Loading (`insmod`)**
- **Temporary**: Module disappears on reboot
- **Session-based**: Only loaded for current session  
- **Use**: Development, testing, debugging
- **Tools**: `./reload.sh` (handles build + load + audio restart)

### **Production Installation (`./install.sh`)**  
- **Persistent**: Module file survives reboot
- **Auto-loading**: Automatically loads on system startup
- **Complete**: Handles dependencies and cross-distribution compatibility
- **Use**: Production systems, end-user installations
